# Аналоги приложений для Практического задания 1

Проект: "Крокодил-онлайн" — веб-игра, где один игрок рисует загаданное слово, а остальные угадывают его в чате.

Ниже — 4 существующих веб-ресурса той же тематики (не мобильные приложения, а именно браузерные игры), и технический аудит по ним по схеме из задания.

> ⚠️ Часть пунктов схемы (сетевые запросы, реальный HTML/CSS, адаптивность при ресайзе, Lighthouse, LocalStorage/Cookies, конкретные счётчики аналитики) можно проверить только вживую, открыв сайт в браузере — у меня нет доступа к DevTools/Lighthouse конкретного устройства и сети пользователя. Эти пункты помечены 🔲 и по каждому ниже расписано, как именно их проверить. Всё остальное (описание, мета-теги, используемый фреймворк по косвенным признакам, наличие рекламы/OAuth) собрано из открытых данных о сайтах.

## Как проверить пункты 🔲 (сделать самостоятельно в браузере)

1. **Архитектура/технологии по сети.** Открыть сайт → DevTools (F12) → вкладка **Network** → перезагрузить страницу (Ctrl+R). Посмотреть:
   - заголовки первого запроса (Response Headers: `Server`, `X-Powered-By` — иногда выдают бэкенд);
   - вкладку **WS** — если во время игры там появляется активное соединение, значит используется WebSocket для синхронизации холста/чата в реальном времени; если WS пусто, но в Network во время игры видны повторяющиеся XHR-запросы — это long polling;
   - вкладку **Sources** — имена файлов бандла (`_next/`, `vue`, `socket.io.js`, `webpack` и т.п.) подсказывают фреймворк.

2. **Семантические элементы HTML5.** DevTools → **Elements** → Ctrl+F (поиск по DOM) → ввести по очереди `header`, `nav`, `main`, `section`, `article`, `aside`, `footer` — сколько раз каждый встречается на странице.

3. **Семантические классы у div.** Если тегов из п.2 почти нет, а вёрстка на div — посмотреть в Elements имена классов у крупных блоков (например `class="header"`, `class="game-container"`, `class="chat-box"`) и выписать 2-3 примера.

4. **Адаптивность.** DevTools → **Toggle device toolbar** (Ctrl+Shift+M) → проверить на нескольких ширинах (375px телефон, 768px планшет, 1024-1440px десктоп) — что перестраивается. Также в **Sources** можно открыть CSS-файлы и поискать `@media` — посмотреть какие брейкпоинты заданы.

5. **Lighthouse.** DevTools → вкладка **Lighthouse** → выбрать Mobile или Desktop и категории (Performance, Accessibility, Best Practices, SEO) → Analyze page load. **Обязательно зафиксировать в отчёте условия проверки**: тип интернета (Wi-Fi/мобильный интернет/LAN) и место (дом/общежитие/университет) — результаты Lighthouse сильно зависят от реальной скорости соединения в момент теста, даже с учётом встроенного троттлинга.

6. **LocalStorage и Cookies.** DevTools → вкладка **Application** → слева **Local Storage** и **Cookies** → открыть домен сайта → посмотреть какие ключи там хранятся (никнейм, настройки, токен авторизации и т.п.).

7. **Маркетинг и аналитика.** DevTools → **Network** → в поле **Filter** по очереди вписать: `analytics`, `metrika`, `facebook`, `pixel`, `tagmanager`, `hotjar`, `doubleclick` — и посмотреть, какие запросы срабатывают (особенно после клика "Accept" на баннере cookies, если он есть).

## 1. skribbl.io

- **Адрес:** https://skribbl.io/
- **Архитектура/логика:** явных признаков крупного JS-фреймворка (Next.js/React/Vue) в разметке не обнаружено — похоже на сайт с рукописным/лёгким JS поверх серверного HTML. Судя по описанию функциональности (рисование и чат обновляются у всех игроков мгновенно, без перезагрузки), в основe WebSocket.
- **Семантические элементы HTML5:** Нет.
- **Семантические классы div:** Много различных, но, например, "panels", "footer", "tos".
- **Адаптивность:** в описании обновления сайта явно заявлена "Mobile support" (редизайн 2022 года), viewport настроен с `user-scalable=no` — сайт точно думает про мобильные экраны. 🔲 конкретные брейкпоинты
- **Lighthouse:** 🔲 (не забыть указать условия проверки)
- **LocalStorage/Cookies:** сайт запоминает выбранные настройки комнаты и, вероятно, ник/аватар между визитами — похоже на LocalStorage. 🔲 подтвердить
- **Маркетинг/аналитика:** явного рекламного блока в разметке не видно (в отличие от трёх сайтов ниже), но это не исключает счётчиков аналитики. 🔲 проверить по фильтрам

## 2. gartic.io

- **Адрес:** https://gartic.io/
- **Архитектура/логика:** в мета-тегах явно присутствует `next-head-count` — это стандартный признак **Next.js** (то есть React-фреймворка). Авторизация через OAuth: Twitter, Google, VK, Discord. На странице виден явный рекламный блок ("Reklam. Zəhmət olmasa, gözləyin..." — азерб. "Реклама, подождите, пожалуйста"). Есть свои приложения под Android/iOS.
- **Семантические элементы HTML5:** 🔲
- **Семантические классы div:** 🔲
- **Адаптивность:** viewport настроен и под мобильные (`interactive-widget=resizes-content`). 🔲 брейкпоинты
- **Lighthouse:** 🔲
- **LocalStorage/Cookies:** должен хранить токены OAuth-сессии, никнейм, выбранную тему/язык. 🔲 подтвердить
- **Маркетинг/аналитика:** реклама подтверждена визуально на странице. 🔲 узнать через Network, какая именно сеть (Google Ads/др.)

## 3. drawasaurus.org

- **Адрес:** https://drawasaurus.org/
- **Архитектура/логика:** тоже собран на **Next.js** (тот же признак `next-head-count`), полноценное SPA — страница явно требует JS ("Sorry, you need JavaScript enabled to play this game!") и не работает без него вообще.
- **Семантические элементы HTML5:** 🔲
- **Семантические классы div:** 🔲
- **Адаптивность:** viewport с `maximum-scale=1, user-scalable=no`. 🔲 брейкпоинты
- **Lighthouse:** 🔲
- **LocalStorage/Cookies:** 🔲
- **Маркетинг/аналитика:** на странице явно видно два рекламных блока (подписаны "ADVERTISEMENT"). 🔲 конкретные счётчики через Network

## 4. drawize.com

- **Адрес:** https://drawize.com/
- **Архитектура/логика:** 🔲 (явного признака фреймворка в мета-тегах не найдено, но сайт очень "тяжёлый" функционально — стриминг, AI-режим CopyCatAI, ежедневные испытания). Для обновления в реальном времени используется WebSocket.
- **Семантические элементы HTML5:** 🔲
- **Семантические классы div:** 🔲
- **Адаптивность:** заточен и под мобильные (есть отдельное приложение в Google Play/App Store + `mobile-web-app-capable`). 🔲 брейкпоинты
- **Lighthouse:** 🔲
- **LocalStorage/Cookies:** на сайте есть явный баннер согласия на cookies с прямой формулировкой — использует cookies "to customize the content, analyze traffic, and display targeted ads" (персонализация контента, анализ трафика, таргетированная реклама). Это уже прямой признак использования аналитики и рекламных трекеров. 🔲 подтвердить конкретные сервисы через Network (там, скорее всего, найдутся Facebook Pixel — на странице есть `fb:app_id` — и Google Analytics/Ads)
- **Маркетинг/аналитика:** подтверждено текстом баннера cookies + наличием `meta fb:app_id` (интеграция с Facebook) + платными тарифами Premium/Business/Classroom (монетизация не только рекламой, но и подпиской).

## Часть 3. Функциональный анализ — что взять в свой проект

| Функция | Где встречается | Приоритет для нашего проекта | Комментарий |
|---|---|---|---|
| Публичные и приватные комнаты | Все 4 | **Высокий** | Базовая механика, без этого игры не будет |
| Гостевой вход без регистрации | skribbl, drawasaurus, drawize | **Высокий** | Низкий порог входа; можно совместить с опциональной регистрацией (нужна для роли админа/статистики по заданию курса) |
| Выбор слова из нескольких вариантов | skribbl | **Высокий** | Несложно реализовать, сильно влияет на играбельность |
| Синхронный холст (Canvas) в реальном времени | Все 4 | **Высокий** | Ядро игры |
| Таймер раунда + постепенные подсказки (открытие букв) | skribbl, drawize | **Средний** | Хорошее дополнение, не критично для MVP |
| Пользовательские наборы слов (CRUD) | skribbl (custom words), drawize (word lists) | **Средний** | Хорошо ложится на требование курса про роль с CRUD-доступом |
| Модерация комнаты (кик/бан/жалоба) | skribbl | **Средний** | Полезно, но не блокирует MVP |
| OAuth-авторизация через соцсети | gartic.io | **Низкий** | Красиво, но для учебного проекта проще email/пароль или гостевой режим |
| Глобальные рейтинги/лидерборды вне комнаты | drawize | **Низкий** | Хорошая идея на будущее, не MVP |
| Реклама/монетизация/подписки | gartic, drawasaurus, drawize | **Не нужно** | Учебный проект без монетизации |
| AI-функции (оценка рисунка нейросетью) | drawize (CopyCatAI) | **Не нужно** | Избыточно для скоупа курсового задания |
| Мультиязычность интерфейса | skribbl, gartic | **Низкий** | Можно ограничиться русским (+опционально английским) |
| Адаптивность под мобильные | Все 4 | **Высокий** | Прямое требование задания (media-запросы) |
